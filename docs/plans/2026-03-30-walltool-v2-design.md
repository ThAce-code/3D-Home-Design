# WallTool V2 设计

> 更新日期：2026-03-30
> 分支：`feature/architecture-core-v1`
> 范围：单层建筑编辑器的画墙交互重构，不涉及多层、门窗、共享墙 face extraction

---

## 1. 背景

当前建筑编辑核心已经具备 `Wall / Zone` 基础数据模型、墙图修复与最小渲染链路，但“画墙”仍然不够产品化，主要问题有两类：

- 用户看到的是厚墙体块，系统实际按墙中线与顶点拓扑工作，缺少显性提示，导致“视觉闭合”和“拓扑闭合”经常不一致。
- 画墙缺少建筑编辑器应有的正交约束与闭合辅助，用户难以稳定拉出严格水平/竖直墙，也难以可靠收口生成 `Zone`。

Pascal editor 对本项目真正有参考价值的不是某个单独算法，而是把 `WallTool` 作为独立编辑工具，把“输入约束、草稿状态、节点提交、几何更新”明确分层。本次 V2 设计沿用这个方向：把 `WallTool` 提升为显式状态机，吸附与闭合成为一等交互规则，而不是事后补救。

## 2. 目标

`WallTool V2` 的目标是：

- 默认支持快速草绘
- 允许用户随时进入严格正交模式
- 提供显性吸附/闭合提示，减少“看着闭合但实际上没闭合”
- 让“画一圈矩形 -> 自动生成一个 zone”成为稳定行为

## 3. 设计原则

### 3.1 混合模式

采用“默认快速草绘 + 临时精确约束”的混合模式：

- 默认自由绘制
- 接近水平/竖直时自动正交吸附
- `Shift` 强制锁定正交
- `Alt` 临时忽略吸附
- `Tab` 进入长度/角度数值输入

这个模式兼顾了新手的顺手感和专业用户对可控性的要求。

### 3.2 墙中线是真实几何

V2 明确承认并展示：系统按墙中线绘制和闭合，而不是按厚墙外轮廓。

这不是内部实现细节，而是必须显性提示给用户的交互事实。

### 3.3 自动闭合是产品能力，不是用户猜测

当终点靠近已有闭合端点时，系统应该显式提示并优先闭合，不允许被较弱的网格吸附或自由点创建抢走。

## 4. WallTool V2 状态机

### 4.1 `idle`

- 尚未选择起点
- 光标移动时只做 hover 与 snap 候选显示

### 4.2 `armed`

- 已确认起点，正在拖动终点
- 持续计算：
  - 当前地面点
  - 端点 snap
  - 正交候选
  - 闭合候选
  - 数值输入草稿

### 4.3 `axis-locked`

- `Shift` 按住后进入
- 当前墙段只允许水平或竖直
- 角度显示为 `0° / 90° / 180° / 270°`

### 4.4 `numeric-entry`

- `Tab` 进入
- 输入长度与角度
- 回车提交
- Esc 退出数值输入并回到草稿态

### 4.5 `closure-preview`

- 当前终点靠近已有端点，且闭合优先级最高
- 高亮目标角点
- 状态文案显示 `释放以闭合`

### 4.6 `commit`

- 提交 `DRAW_WALL`
- 触发 topology repair
- 成功后保留工具，等待下一段连续绘制

### 4.7 `cancel`

- `Esc` 或右键取消当前草稿
- 不修改文档

## 5. 吸附与约束优先级

V2 统一采用以下优先级，避免用户感觉“系统在乱吸”：

1. 显式闭合点
2. 现有端点 snap
3. 强制正交锁定
4. 自动正交建议
5. 边上线投影
6. 网格吸附
7. 自由点

规则重点：

- 只要存在闭合候选，不允许较弱规则抢走。
- `Shift` 一旦按下，方向约束优先于普通自由移动。
- `Alt` 按下时临时关闭端点/网格/闭合吸附，但不关闭显性数值输入。

## 6. 显性提醒

V2 必须给用户明确反馈，不再让用户自己猜当前系统如何解释鼠标点位。

### 6.1 固定工具状态

进入 `WallTool` 后，界面固定显示：

- `正在画墙`
- `按墙中线绘制`
- `Esc 取消`

### 6.2 光标附近提示

根据当前状态动态显示：

- `端点吸附`
- `正交吸附`
- `正交锁定`
- `释放以闭合`
- `按 Tab 输入长度`

### 6.3 几何预览

- 草稿线显示中线
- 墙厚预览只作为体量提示，不可替代中线
- 闭合目标角点高亮
- 可选显示长度与角度 HUD

## 7. 闭合判定与容差策略

当前固定 `0.05` 世界坐标端点容差过于脆弱，无法支撑真实交互。V2 改为双阈值判定：

- 屏幕空间阈值：保证缩放级别变化下仍好用
- 世界空间阈值：防止远距离错误吸附

收口时规则如下：

- 若终点落在已有端点候选内，直接复用已有 `vertexId`
- 若用户正在补“最后一条边”，闭合候选优先于创建新顶点
- 若 close miss 很近但超出小阈值，可进入“软闭合建议”显示，不直接提交

## 8. 与当前核心的边界

V2 仍沿用当前单层架构与基础 topology repair，但重新定义交互入口：

- `editing/tool` 负责输入解释、草稿、吸附、约束
- `core topology` 负责最终稳定化
- `viewer` 负责提示和预览

V2 暂不解决：

- 多层编辑
- 门窗 opening
- 共享墙 planar graph face extraction
- 最终专业级 room solver

## 9. 验收标准

- 用户自由画矩形，稳定生成一个 `zone`
- 用户按 `Shift` 时，只能画水平/竖直墙
- 用户接近正交时，会自动吸附并显示角度提示
- 用户靠近收口端点时，会高亮并提示 `释放以闭合`
- 用户点可见墙面时仍能选中墙
- 用户点封闭空间内部时仍能选中 `zone`
- 不再频繁出现“视觉闭合但拓扑未闭合”的情况

## 10. 推荐实施策略

V2 不建议继续在现有 `ArchitectureScene` 组件事件上堆逻辑，而应逐步把画墙行为上提为真正的 `WallTool`：

- `WallToolController` 负责状态机
- `wallSnapping` 负责候选点与约束
- `WallDraftOverlay` 负责提示与预览
- 现有 reducer / topology 保持为提交层

这条路线最接近 Pascal 的编辑器分层方式，也最利于后续接入 `ZoneTool`、`SlabTool` 和门窗开洞。
